# Omarchy YubiKey 0.5.0

Manage the OpenPGP and resident SSH keys on a connected security key from the
Security keys page. This release integrates and revises the contributions in
[PR #2](https://github.com/marselnenaj/omarchy-yubikey/pull/2) and
[PR #4](https://github.com/marselnenaj/omarchy-yubikey/pull/4).

## OpenPGP card

- Import into a private staging keyring first. Only the public certificate
  matching all populated card-slot fingerprints enters the account's keyring;
  an unrelated key returned by the card URL triggers keyserver fallback.
- Distinguish actual references to this card from local secret material,
  references to another card and missing keys, separately for signing,
  encryption and authentication. Account for expiry, revocation and disabled
  keys. Ownertrust is shown separately from hardware readiness.
- Offer explicit ownertrust and confirmed removal. Removal refuses local
  secret material and repeats the inspection after confirmation.
- Show a selectable public fingerprint and optionally the public name/email.
  Card serials, URLs, secret material and raw command output stay out of the UI.

## Resident SSH keys

- Download key handles through ssh-keygen into a private temporary directory,
  install complete matching pairs without overwriting existing files, and
  roll back files created for an interrupted pair copy.
- Show public applications and selectable fingerprints. Remove by stable
  identity instead of row number, rechecking the selected files after confirmation.
- Offer Git-host configuration in one managed file under
  `~/.ssh/omarchy-yubikey/config`, with a global Include in the account's SSH config.
  Preview effective settings with `ssh -G` before applying changes. Detect manual
  edits and support adding, removing and reimporting keys for an existing host.
- Default connection reuse to off, explicitly overriding inherited multiplexing
  settings. A positive reuse duration is opt-in; existing authenticated sessions
  remain open when a copied key is removed.

The bundled setup translation loader is selected explicitly, fixing its name
collision with Omarchy 4.5's translation type. Public identity fields wrap at
narrow widths and render as plain text, with control characters removed.

## Install and upgrade

```sh
omarchy plugin add https://github.com/marselnenaj/omarchy-yubikey.git --enable
```

For an existing Git-managed installation:

```sh
omarchy plugin update yubikey.setup
```

The suite/setup plugin is **0.5.0**. The standalone lock/Polkit plugins remain
**0.3.0** and the Rust Keyring helper remains **0.2.0**. Existing PAM enrollments
and helper stores remain compatible. Updating source does not apply PAM changes,
import keys or enable SSH connection reuse; those operations remain explicit.

Preview users who created legacy `config.d/<host>.conf` files should inspect and
remove those manually before enabling the new managed configuration. They are
not automatically adopted or overwritten. Review the effective-settings preview,
especially if the account already configures the same Git hosts.

See [OpenPGP](../openpgp.md), [SSH](../ssh.md),
[setup and removal](../control-center.md) and the [security model](../security-model.md).

## Downloads

The source archive contains the setup plugin, both authentication-plugin templates
and Rust helper source, built from the exact release tag. `SHA256SUMS` covers the
attached archive. No prebuilt executables or release signatures are supplied.
The plugin commands follow the default branch; the tag/archive is a fixed snapshot.

## Verification and limits

Local checks passed **120 Python**, **17 JavaScript** and **7 Rust** tests, Rust
formatting, catalog consistency, shell syntax, publication checks and source/history
secret scans. Tests include isolated real GnuPG keyrings, wrong/multiple downloaded
certificates, local-secret deletion refusal, real OpenSSH configuration resolution,
interrupted writes, removal/reimport and stale key selection.

Native Quickshell checks passed in English, German and Arabic/RTL fallback, including
640-pixel windows, keyboard confirmation/cancellation, stable action arguments and
long public fingerprints. Visual checks use synthetic identities only.

This release does not claim fresh hardware authentication, reader/pinentry,
SSH-server multiplexing, locked-session recovery or boot qualification for the
revised implementation. Those still need testing on the target key and environment.
