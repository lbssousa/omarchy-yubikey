# Omarchy YubiKey 0.1.1

Adds optional **LUKS2 disk-unlock enrollment and a manual boot-integration
guide**, based on the existing local systemd/FIDO2 approach. The default desktop
installer does not change disk encryption or boot files.

- Start separately with `./install.sh --luks --device /dev/your-luks-partition`.
  Add `--check` for read-only prerequisite checks.
- Explicit device selection, a passphrase test, private before/after header
  backups, PIN-plus-touch enrollment, optional backup keys and a recovery key.
- Test the newly enrolled token without mapping the already-open root device.
  Existing slots are preserved; no automatic slot deletion or header restoration.
- Optional mkinitcpio hook conversion retains hardware choices and snapshot
  support. Boot installation, fallback-image preservation, image inspection and
  reboot tests are deliberate manual steps in [the LUKS guide](../luks.md).
- Broader publication checks reject disk UUIDs and boot/runtime artifacts.
  Only generic source and synthetic tests are distributed, with GitHub noreply
  commit attribution. Local headers, mappings, credentials and chat logs are
  excluded.

## Downloads and component versions

`omarchy-yubikey-0.1.1-source.tar.gz` contains the source suite. `SHA256SUMS`
records its SHA-256 checksum. There are no prebuilt executables or signatures.
The standalone lock/Polkit plugins and Rust helper remain at **0.1.0** because
their code is unchanged; those separate releases do not need updating for LUKS.

## Validation and limits

The new isolated tests cover enrollment ordering, newly added token selection,
preservation of existing slots, cancellation/failure behavior, private backup
permissions, and conversion/refusal of initramfs hooks. Existing software checks
remain applicable. These are software tests, not a new hardware enrollment or
boot qualification. The generalized procedure has not been freshly tested through
a full reboot; review the [guide](../luks.md) and [security model](../security-model.md)
before use. No changes were applied to the source machine's encryption or boot
configuration while preparing this release.
