# Omarchy YubiKey 0.5.1

This security release fixes the optional Keyring helper's build dependency for
[RUSTSEC-2026-0418](https://rustsec.org/advisories/RUSTSEC-2026-0418.html), reported
by HANCORE-linux in the
[marketplace review](https://github.com/omacom/omarchy-plugin-marketplace/issues/13898#issuecomment-6681099260).

## Build-output disclosure

The previous lockfile combined `libz-sys 1.1.30` with `cc 1.8.0`. On normal Unix
dynamic-zlib builds, a dependency printed its compiler command, including the
inherited environment, into Cargo's saved build-script output and verbose logs.
Secrets could be exposed if that environment contained them and the resulting
logs, target directory or cache became accessible to an unauthorized reader.
This is not evidence that current CI secrets were exposed.

The lockfile now selects `libz-sys 1.1.31`, whose upstream patch removes that
logging. The fix covers the installer, CI and manual Cargo builds while retaining
normal compiler and library environment settings. Existing authentication,
enrollments and encrypted stores remain compatible.

The lockfile also replaces yanked `async-executor 1.14.0` with **1.14.1**.
Upstream [fixes a use-after-free during executor shutdown](https://github.com/smol-rs/async-executor/releases/tag/v1.14.1).
The new yanked-dependency check identified this additional update.

Updating cannot erase earlier output. If an affected build ran with secrets,
review access to its logs, `target/` directory and shared caches. Remove affected
copies and rotate secrets if unauthorized access occurred or cannot be excluded.
Do not upload old build output for diagnosis. Source-only plugin installations
that never built the helper did not execute this build script.

## Ongoing checks

- Weekly Dependabot version updates cover Cargo, including transitive
  dependencies, and pinned GitHub Actions. Updates are reviewed, not auto-merged.
- A daily RustSec workflow also runs on pushes and pull requests, failing on known
  vulnerabilities, unsoundness and yanked crates. Informational maintenance
  notices remain visible; see [the policy](../../SECURITY.md#dependency-maintenance).
- A regression check builds the real locked zlib dependency with two synthetic
  environment values and checks both persisted stdout and verbose Cargo output.

## Install and upgrade

```sh
omarchy plugin update yubikey.setup
```

For a source checkout, update it before rebuilding with `cargo build --release
--locked`. Updating the plugin/source alone does not rebuild an already installed
Keyring binary or re-enroll any credentials. The issue occurs while building;
re-enrollment is not required for this fix.

The setup plugin is **0.5.1**; standalone lock/Polkit plugins remain **0.3.0** and
the Rust helper's application version remains **0.2.0**. Downloads contain source
from the release tag and a SHA-256 checksum file, without prebuilt executables.

## Verification scope

Using fresh isolated builds, the old dependency reproduced disclosure of both
synthetic canary classes and the patched dependency did not. The checks exercised
system/dynamic zlib with custom `CC`/`CFLAGS`, persisted build-script output and
verbose Cargo output. No real secrets or hardware credentials were used.

The release build, 120 Python tests, 17 JavaScript tests, 7 Rust tests, formatting,
translation consistency, shell syntax, publication checks and source/history
secret scans passed locally. The current RustSec database reports no known
vulnerabilities in this lockfile; the three documented maintenance notices remain.

This dependency change does not claim new hardware, PAM, keyring-session or boot
qualification. The existing [0.5.0 features and limits](0.5.0.md) still apply.
