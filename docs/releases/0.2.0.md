# Omarchy YubiKey 0.2.0

**Prerelease:** software checks pass; real hardware/PIN interaction and actual
session-lock recovery still need manual qualification before a stable promotion.

Adds **PIN-aware PAM authentication, explicit password fallback and opt-in signed
enrollment transfer through a separate private Git repository**.

- Guided setup defaults to FIDO2 PIN plus touch. Touch-only remains an explicit
  compatibility choice; set a PIN on the key before enrolling in PIN mode.
- Key failure/timeout reaches a small Linux-PAM conversation gate before the
  existing sudo/Polkit password stack. sudo requires the literal choice `password`;
  Polkit displays **Use password**. Missing/broken/cancelled gate conversations
  fail closed. Automatic fallback remains a deliberate installer choice.
- The lock selects one authentication method at a time, supports key PIN prompts,
  clears input when switching methods and offers **Use password / Retry key**.
  It does not automatically retry a failed PIN or downgrade after key failure.
- Polkit displays the actual PAM response prompt and does not collect secrets
  while waiting for a touch. `authpending_file` remains upstream's notification
  mechanism; it is not used as an authentication decision.
- Explicit color-module qualification avoids a name collision on newer Qt.
- `./install.sh --sync export/import` signs per-account snapshots with OpenSSH,
  verifies separately pinned account-specific trust, shows changes, requires an
  interactive import and rejects accepted/older revisions. Git operations remain
  unprivileged and user-managed. Signed snapshots are **not encrypted**.
- Imports replace the selected account's mapping, preserving other users and
  propagating removals. Root-only revision state, backups and a shared transaction
  lock protect reviewed installation. First import requires a known minimum revision.

## Upgrade and component versions

Suite and shell plugins are **0.2.0**. The optional Rust Keyring helper remains
**0.1.0**, unchanged and touch-only; PAM PIN mode does not protect its saved store.
The guided installer explicitly explains this before helper enrollment.

Updating plugin/source files does not rewrite installed PAM. While unlocked,
keep a recovery root shell open and rerun the reviewed installer to choose the
new policy. Only known standard Arch stacks and this project's known prior
configuration are migrated automatically. Custom stacks stop for manual review.
Standalone plugin updates need the matching reviewed suite PAM setup for the
new policy; the fallback gate is built locally from source, not bundled as a binary.

## Validation and limits

Software checks include Rust tests, Node tests of the actual lock service
functions and Polkit prompt model, Python setup/rollback/transfer tests, native
Linux-PAM integration tests, shell syntax, plugin validation and QML lint.
Native PAM tests load the real gate in an isolated configuration with synthetic
authenticators; transfer tests use real signatures from disposable SSH keys.
They cover failed PINs, cancellation, missing gate, confirmation without a valid
password, input routing, tampered exports, incorrect trust, old revisions, account/
origin binding, removals, protected paths and interrupted writes.

Local validation passed 49 Python tests (including 6 native PAM conversation
tests), 9 Node tests and 5 Rust tests. The lock's PIN, touch-waiting and password
views also rendered offscreen without QML errors; this is visual validation only.

No active system PAM, real enrollment, encrypted store, boot files or enabled
authentication plugins were changed during development. Real-key PIN interaction,
real session-lock recovery and multi-machine transfer still require manual
qualification on a recoverable setup. This release is not an independent audit
or a claim of mandatory two-factor authentication.

Source archives and SHA-256 checksums are supplied; no prebuilt executables or
release signatures. Enrollment signatures belong to each user's sync workflow,
not to the source-release verification process. See [PAM setup](../pam-setup.md),
[enrollment sync](../enrollment-sync.md) and [security model](../security-model.md).
